## 2. หลักการ: "คาบเรียน" เป็นแกนกลาง

```
 ตั้งค่าล่วงหน้า (ก่อนเปิดเทอม)            ระหว่างเทอม (ทุกคาบ)                    หลังคาบ / สิ้นเทอม
 ─────────────────────────            ─────────────────────────                ─────────────────────
 ① ตารางเรียน ── สร้างคาบทั้งเทอม ──►  คาบเรียน (แกนกลาง) ◄── รายชื่อ/กลุ่ม (หลังลงทะเบียน)
        │                  ▲               │
        │           ② จองห้อง (ทุกคาบ = 1 การจอง; สอนชดเชย/เตรียมแล็บ/วิจัย/สอบ ใช้ตารางเดียวกัน)
        │                                  │
 บทปฏิบัติการ ── แม่แบบใบงาน ──────────►  ⑤ ใบงานของคาบ = แม่แบบ × จำนวนกลุ่ม/คน/ห้อง
 (รายการ + กฎการคิดจำนวน)                   │  ยืนยัน ──► จองของในคลัง ──► งานเตรียมของของนักวิทย์
        │                                  │
 ④ คลังวัสดุ (ล็อต/ราคา/วันหมดอายุ) ◄──── เบิกจริง / คืนของที่เหลือ / ของเสีย
                                           │
                                     ③ สแกนหน้าเช็คชื่อ ── จำนวนคนมาจริง, กลุ่มที่มา
                                           │
                                     ⑥ ต้นทุน = ของที่ใช้จริง × ราคาล็อต
                                        → ต่อคาบ / ต่อบท / ต่อวิชา / ต่อหัว นศ.
                                        → พยากรณ์ของที่ต้องซื้อเทอมหน้า
```

| จาก → ไป | ข้อมูลที่ส่งต่อ | ประโยชน์ |
|---|---|---|
| ตารางเรียน → จองห้อง | คาบ = การจองห้อง | ห้องไม่ซ้อน, ย้าย/งดคาบ = แก้/ปล่อยห้องในตัว |
| ตารางเรียน → ใบงาน | คาบไหน บทไหน ห้องไหน วันไหน | ใบงานทุกคาบเกิดเองตั้งแต่ต้นเทอม |
| รายชื่อ → ใบงาน | จำนวน นศ., กลุ่ม, ห้องย่อย | คำนวณจำนวนของตามกฎ |
| ใบงาน → คลัง | รายการ + จำนวน + วันที่ต้องเตรียมเสร็จ | จองของล่วงหน้า เตือนของไม่พอ |
| คลัง → ต้นทุน | ของที่ออกจริง × ราคาล็อต | ต้นทุนจริง |
| เช็คชื่อ → ต้นทุน | จำนวนคนมาจริง | ต้นทุนต่อหัว, อัตราขาดใช้ปรับ % เผื่อ |
| เช็คชื่อ → คลัง | กลุ่มที่มา/ตัวแทนกลุ่ม | ยืม-คืนอุปกรณ์รายกลุ่ม |
| จองห้อง (วิจัย/โครงการ) → ต้นทุน | วัสดุที่เบิกในการจองนั้น | ต้นทุนลงโครงการ ไม่ปนกับวิชา |
| ทั้งหมด → แผนเทอมหน้า | คาบที่วางแผน × กฎใบงาน − ของในคลัง | **รายการของที่ต้องซื้อก่อนเปิดเทอม** (ก่อนมีรายชื่อใช้จำนวนที่นั่งรับ แล้วคำนวณใหม่หลังนำเข้ารายชื่อ) |

## 3. หลักออกแบบที่ต้องถูกตั้งแต่แรก

1. **คลัง = บัญชีความเคลื่อนไหว** — ไม่แก้ยอดตรงๆ ทุกอย่างเป็นรายการ: รับเข้า / จอง / เบิก / คืน / ปรับยอดจากตรวจนับ / หมดอายุ-เสีย / ย้ายที่เก็บ · ยอด 3 แบบ: มีจริง, จองแล้ว, ใช้ได้ · ตรวจนับ = รายการปรับยอดพร้อมเหตุผล
2. **ล็อต** (วันที่รับ, ราคา, วันหมดอายุ, ที่เก็บ) → คุมวันหมดอายุ + ต้นทุนแบบ FIFO
3. **สูตรเตรียม** — ของที่เตรียม (จานอาหารเลี้ยงเชื้อ, สารละลาย) แปลงเป็นวัตถุดิบในคลัง เช่น 1 จาน = 20 mL, 1 L ใช้ผง 50 g
4. **หน่วยนับ** — หน่วยซื้อ / หน่วยใช้ / อัตราแปลง, ปัดขึ้นตามขนาดบรรจุตอนสั่งซื้อ
5. **วัสดุสิ้นเปลือง ≠ ครุภัณฑ์** — สิ้นเปลือง = ตัดยอด · ครุภัณฑ์ = จองเวลา (ใช้กลไกเดียวกับจองห้อง) + ยืม-คืน + ค่าเสื่อม
6. **ต้นทุน** — รอบแรก: วัสดุสิ้นเปลือง + ของเสีย/หมดอายุ · ทีหลัง: ค่าเสื่อมครุภัณฑ์ (เก็บชั่วโมงใช้งานไว้ก่อน), ค่าแรงเตรียมแล็บ (ทางเลือก)
7. **บทบาทใหม่ "นักวิทยาศาสตร์/เจ้าหน้าที่ห้องแล็บ"** — รับของ เตรียมของ ตัดสต็อก ตรวจนับ (อาจารย์ = ยืนยันใบงานวิชาตัวเอง, แอดมิน = รายงาน/ต้นทุนทั้งหมด)
8. **ความถูกต้องของข้อมูล** — รายการคลัง/จองห้อง ทำเป็นฟังก์ชันในฐานข้อมูลแบบ transaction + ล็อกแถว (กันสองคนตัดพร้อมกัน) · ใบงานที่ยืนยันแล้วเก็บสำเนาจำนวน+ราคา (snapshot)
9. **โครงโค้ด** — แยกหน้าเว็บต่อระบบ (staff.html ตอนนี้ ~1,700 บรรทัด) ใช้ไฟล์กลางร่วมกัน · ฝั่งเซิร์ฟเวอร์แยก Edge Function ต่อระบบ ใช้ `_shared/` ร่วมกัน
10. **ข้อมูลเริ่มต้น** — นำเข้าจาก Excel (รายการวัสดุ, สต็อกตั้งต้น, กฎใบงาน) ใช้ตัวอ่าน Excel ที่มีอยู่ (`lib/xlsx-read.js`)

## 4. ระบบจองห้อง (ทำถัดไป)

**การตัดสินใจของผู้ใช้ (5 ต.ค. 2569): "การระบุห้องเรียนของคาบเรียน เปรียบเสมือนการจองห้อง"**

### 4.1 โครงข้อมูล (migration 014 — ร่างแล้ว `supabase/migrations/20261005000014_room_reservations.sql` ยังไม่ apply)
- ตาราง `room_reservations` — การใช้ห้อง**ทุกประเภท**รายครั้ง: `kind` = class | makeup | prep | reading | research | exam | event | maintenance | other · `status` = pending | approved | rejected | cancelled · `schedule_id` (มี = คาบเรียน) · `section_id`, `series_id` (จองซ้ำรายสัปดาห์), title, purpose, attendees, ผู้ขอ/ผู้อนุมัติ
- **ฐานข้อมูลบังคับห้ามซ้อน**: exclusion constraint (btree_gist) — ห้องเดียวกัน การจองที่ `approved` ทับเวลากันไม่ได้
- **trigger ซิงก์จาก `schedules`**: สร้าง/ย้ายเวลา/ย้ายห้อง/งด/ลบคาบ → การจองเปลี่ยนตามเอง (งด = cancelled = ปล่อยห้อง)
- `room_bookings` เดิมเหลือบทบาทเป็น "หัวเรื่องของชุดคาบ" (1 ต่อกลุ่มเรียน/การสอนชดเชย)
- ข้อมูลจำลอง: ย้าย CHM102L ไป "ห้องทดสอบ C" (พิกัดเดียวกับห้อง A) แล้ว เพราะ CHM101L มีคาบทดสอบทุกชั่วโมงในห้อง A — ตรวจแล้วไม่มีคาบชนกันเหลือ

### 4.2 ผลต่อของเดิม
- ตั้งค่าเทอม: ห้องชน **บล็อก** (เดิมแค่เตือน) — ตรวจชนกับการจองทุกประเภท ไม่ใช่แค่คาบเรียน
- ลำดับการบันทึกคาบ: ลบ → แก้ → สร้าง (กันชนกันเองชั่วคราวในกลุ่มเรียนเดียวกัน) · ช่วงเวลาวันเดียวกันในกลุ่มเรียนเดียวกันห้ามทับกัน
- error ห้องชนจากฐานข้อมูล (23P01) แปลเป็นข้อความไทยที่บอกว่าชนกับอะไร

### 4.3 สิ่งที่จะสร้าง
- Edge Function ใหม่ `booking`: `rooms_board {from,to}` (ห้อง + การจอง + วันหยุด), `booking_preview` (ทุกครั้งที่จะเกิด + ชนอะไร), `booking_create` (ครั้งเดียว/ซ้ำทุกสัปดาห์), `booking_cancel` (ครั้งนี้/ทั้งชุดที่เหลือ), สอนชดเชย = สร้างคาบใหม่ให้กลุ่มเรียน (+ ย้ายบทจากคาบที่งด)
- หน้า "🏫 ห้อง" (`#rooms/<date>`): ตารางห้องว่าง ห้อง = แถว, เวลา = คอลัมน์ · คาบเรียนสีตามวิชา, การจองอื่นสีแยกตามประเภท · กดช่องว่าง = จอง · กดบล็อก = รายละเอียด/ยกเลิก
- ปฏิทินเดิมแสดงการจองนอกตารางด้วย (ภายหลัง)

### 4.4 ค่าเริ่มต้นที่ใช้ (ผู้ใช้ยังไม่ได้ยืนยัน)
- อาจารย์/แอดมินจองได้ และ **อนุมัติอัตโนมัติถ้าไม่ชน** (โครงรองรับ "รออนุมัติ" ไว้แล้ว สำหรับนักศึกษา/คนนอกในอนาคต)
- ทุกห้องชนแล้วบล็อก (ยังไม่มีห้องแบ่งโซน)
- ยังไม่บังคับสแกนหน้าเข้าใช้ห้องสำหรับการจองนอกคาบ
- การจองประเภทคาบเรียนแก้ผ่าน "ตั้งค่าเทอม" เท่านั้น ไม่แก้จากหน้าจองห้อง

## 6. คำถามที่รอผู้ใช้ตอบ

**จองห้อง**
1. ใครจองได้ — เฉพาะอาจารย์/นักวิทย์ หรือ นศ.โครงงาน/คนนอกขอจองได้ (ต้องมีหน้าขอจองไม่ต้องล็อกอิน)
2. ใครอนุมัติ — เจ้าของห้อง, หัวหน้าแล็บคนเดียว หรืออาจารย์จองแล้วผ่านอัตโนมัติ
3. การจองนอกคาบ ต้องสแกนหน้าเข้าใช้ห้องไหม (บันทึกการใช้ห้อง/ความปลอดภัย)
4. มีห้องที่ใช้ร่วมกันได้พร้อมกัน/แบ่งโซนไหม

**คลัง + ต้นทุน**
5. วิธีคิดต้นทุน: FIFO ตามล็อต (แนะนำ) หรือราคาเฉลี่ย
6. ตัดสต็อกจังหวะไหน: ตอนเตรียมเสร็จ + รับคืนหลังคาบ (แนะนำ) หรือตัดหลังคาบครั้งเดียว
7. ที่เก็บของ: คลังกลางที่เดียว หรือแยกตามห้อง/ตู้
8. มีเอกสารสูตรเตรียมอาหารเลี้ยงเชื้อ/สารละลายไหม
9. ต้นทุนรอบแรก: เฉพาะวัสดุสิ้นเปลือง หรือรวมค่าเสื่อมครุภัณฑ์ด้วย

**ใบงาน** — คำถามค้าง 7 ข้อใน `docs/worksheet-design.md` หัวข้อ 8 / `Context.md` หัวข้อ 7
